IFRS taxonomy is mandatory for international EDGAR filers

Querying the SEC EDGAR XBRL API using US-GAAP taxonomy tags alone silently drops Foreign Private Issuers, eliminating half the public transport universe.

The trap

Programmatic data pipelines querying the SEC EDGAR data.sec.gov/api/xbrl/companyfacts endpoint extract structured financials tagged in XBRL.

Most extraction scripts query standard us-gaap taxonomy concepts (such as us-gaap/Revenues). However, non-US companies listed on US exchanges file annual reports on Form 20-F or Form 40-F under International Financial Reporting Standards (IFRS).

These filers tag accounts exclusively using the ifrs-full taxonomy (such as ifrs-full/Revenue).

When a pipeline requests only us-gaap concepts, queries for IFRS filers do not return an error or schema mismatch. They return an empty JSON object. The pipeline interprets this as missing data and drops the filer from the dataset.

Where it was observed

Initial extraction routines querying only us-gaap tags silently omitted over 50% of the cross-border transport monitoring universe, including major international ocean, air, and logistics operators.

How to spot it

Inspect SEC submission forms for Form 20-F or Form 40-F filings.

Configure extraction routines to query dual taxonomy endpoints in parallel: - Request us-gaap concepts alongside corresponding ifrs-full concepts. - Map ifrs-full/Revenue and ifrs-full/GrossProfit directly to the appropriate operating model revenue definitions. - Treat empty tag responses as schema branch misses rather than non-filing events before validating against the metric dictionary.
