What the work is

A vast proportion of the world's ground transportation, LTL networks, and bulk maritime shipping runs on legacy IBM AS/400 (iSeries) platforms, RPG/COBOL programs, and custom mainframe databases. While these systems are stable and process high-volume transactions with near-zero downtime, their green-screen terminal interfaces (5250/3270) and lack of native REST APIs make it nearly impossible to connect to modern shipper APIs, mobile apps, or digital freight networks.

This pattern executes non-invasive legacy modernization without undertaking high-risk core system replacements.

First, engineers implement real-time Change Data Capture (CDC) pipelines (using tools such as Debezium, Qlik Replicate, or IBM InfoSphere). The CDC engine monitors underlying AS/400 database transaction journals in real time, capturing new loads, status changes, and billing updates without imposing query locks or performance overhead on operational dispatch tables.

Second, teams build modern REST/JSON and GraphQL API wrappers around legacy business logic. By wrapping legacy RPG and COBOL programs with containerized microservices, external trading partners can tender freight, receive status pings, and pull rates programmatically.

Third, the solution deploys modern web and mobile user interfaces that replace 5250 green screens. Dispatchers and billing specialists interact with modern web frontends that streamline multi-screen terminal workflows into unified single-page views while submitting validated transactions back into the legacy core.

How it differs by model

  • Model 1 (Truckload Brokerage): Modernizes legacy brokerage databases (e.g. legacy McLeod or TMW installs) with modern digital booking APIs, allowing programmatic integration with external carrier networks and digital load boards.
  • Model 4 (Asset Truckload): Wraps legacy fleet management and dispatch systems to connect seamlessly with modern electronic logging devices (ELDs), cab telematics tablets, and automated maintenance tracking tools.
  • Model 5 (LTL Network): Protects proprietary LTL rating and linehaul dispatch engines that represent 30+ years of accumulated contractual tariff rules. API wrappers expose these complex rating calculations to customer web portals without altering core RPG algorithms.
  • Model 6 (Ports & Terminals): Modernizes legacy terminal inventory and rail booking mainframes with web-based truck appointment systems and real-time gate OCR interfaces.
  • Model 8 & Model 13 (Bulk Marine): Modernizes custom barge voyage accounting and contract management systems without disrupting proven vessel accounting and laytime calculation logic.

Unit of work and its economics

  • Unit of work: Modernized legacy API endpoint, wrapped green-screen workflow, or deployed CDC event streaming pipeline.
  • Modernization economics: Comprehensive API wrapper and CDC modernization projects cost $220,000 to $650,000 over 4 to 8 months.
  • Capital preservation: Avoids a full core ERP/TMS replacement, which typically costs $8M to $35M and carries a 50%+ catastrophic failure or abandonment risk.
  • Operational speed: Deploys customer-facing digital booking and automated visibility in months rather than the 2 to 4 years required for a complete core platform replacement.

Preconditions

Non-invasive modernization requires thorough technical discovery:

  1. Access to underlying database schemas and copybooks: Source DDS/DDL definitions, RPG/COBOL data structures, and transaction journal configurations.
  2. Transaction journal activation: Enabling IBM i journal receivers without exhausting disk storage or slowing down high-volume batch runs.
  3. Documented green-screen navigation flows: Mapping complex 5250 function key sequences (F3 exit, F6 add, F12 cancel) and input validation rules.

Schema discovery, journal configuration, and terminal workflow mapping consume 65% of initial project effort.

Commercial structures

  • Technical discovery, proof-of-concept API wrappers, and CDC pipeline setup utilize fixed-price-diagnostic-then-build.
  • Continuous wrapper engineering, frontend development, and microservice expansion utilize time-and-materials.
  • Embedding specialized legacy integration engineers alongside in-house IT teams utilizes forward-deployed-engineer-embedded.

What has already failed here

The history of enterprise logistics is littered with catastrophic failures where operators attempted to rip and replace working AS/400 systems with off-the-shelf enterprise software.

As analyzed in monolithic ERP and WMS rip-and-replace, the most prominent example is Deutsche Post DHL Group's 2015 cancellation of its "New Forwarding Environment" (NFE) project. DHL attempted to replace its disparate legacy forwarding systems with a unified SAP suite; after spending €345 million, the project collapsed, paralyzing billing and forcing a complete write-off. Similarly, major US truckload carriers that attempted full rip-and-replace TMS projects suffered severe operational chaos and lost significant enterprise value.

Where the hard part sits

The vendor pitch promises effortless API wrapping that magically transforms legacy green screens into modern web apps overnight.

The operational reality is batch window contention and database locks. Legacy transport applications rely on massive overnight batch jobs for driver pay, billing consolidation, and ledger balancing. If modern API wrappers execute poorly designed real-time SQL queries against operational DB2/400 tables during batch processing, they cause record locks that crash overnight billing. Modernization must utilize decoupled streaming architectures (Kafka + CDC) to prevent read-query contention on operational tables.

Where it applies

  • US: Exceptionally high prevalence of AS/400 (IBM iSeries) in trucking; hundreds of mid-sized and large asset carriers operate on legacy TMW, McLeod, or custom iSeries platforms.
  • UK/Europe: Legacy road freight operators frequently run proprietary UNIX-based freight rating systems that require POSIX-compliant API wrappers and EDIFACT gateways.
  • Southeast Asia: Major state-owned port terminals, railway networks, and legacy shipping agencies run legacy mainframe systems requiring terminal emulation wrapping and screen-scraping pipelines.
